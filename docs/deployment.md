# Публикация и безопасный выпуск

## Существующий механизм

Сайт подготовлен для GitHub Pages из корня ветки `gh-pages`.
В README этой ветки описана настройка Settings → Pages →
Deploy from a branch → gh-pages → / (root).
`.nojekyll` отключает обработку Jekyll; сайт представляет собой статические HTML, CSS и JavaScript.
После структурного рефакторинга в `develop` для будущего выпуска необходимы
`index.html` и весь каталог `assets` с сохранением относительных путей.
Нельзя выпускать только обновлённый HTML без связанных файлов CSS/JS.

GitHub Actions подтверждает успешные build и deploy для коммита
`df83ea52db23d2ecd52d6c830c70c73ccfc60753`:
[pages build and deployment, 1 ноября 2026 года](https://github.com/Timur-Tavasapar/Tavaspar-education/actions/runs/41298576475).
Этот результат не доказывает текущую доступность адреса или прохождение тестов.
В исходных файлах нет собственного workflow сборки/тестирования.

## Ветки

- `develop` и временные ветки от неё — разработка.
- `gh-pages` — производственная ветка; изменение может инициировать публикацию.
- `main` — первоначальный README; текущая настройка не обновляет её.
- Push в `develop` сам по себе не является поручением на выпуск.
- Перед будущими изменениями проверять актуальные настройки Pages и workflows.

## Безопасный порядок выпуска

1. Подготовить изменения в `develop`, пройти применимые проверки из `testing.md`.
2. Указать точный коммит-кандидат, состав изменений, результаты проверок
   и известные ограничения. Зафиксировать текущий SHA `gh-pages` для отката.
3. Получить прямое разрешение владельца на публикацию конкретного обновления.
   До разрешения не менять `gh-pages`, настройки Pages и не запускать развёртывание.
4. После разрешения повторно проверить удалённые ветки и отсутствие новых
   производственных изменений. Не перезаписывать их и не использовать force push.
5. Выпустить согласованное изменение обычным коммитом/слиянием в `gh-pages`
   в рамках разрешённого объёма. Проверить diff выпуска; не переносить
   инструкции и внутреннюю документацию в production автоматически.
6. Проверить результат Actions и затем публичную страницу, маршруты и ресурсы.
   Сообщить SHA выпуска и фактические результаты.

## Откат

Предпочитать новый revert-коммит в `gh-pages`, а не переписывание истории.
Откат также меняет production и требует разрешения, если оно не было дано заранее.
После отката проверить Actions и сайт.

## Ограничения

Инструкции в AGENTS.md не являются технической защитой веток.
Защита веток, обязательные проверки и изменение настроек репозитория
этой задачей не настраиваются. Статический GitHub Pages не исполняет
серверную авторизацию или код работы с БД.
