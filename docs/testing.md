# Минимальные проверки

## Текущее состояние и запуск

В исходном прототипе нет автоматических тестов, тестового раннера и сборки.
Успешный workflow GitHub Pages подтверждает развёртывание, а не тестирование функций.

Для ручной проверки из корня рабочей копии можно запустить:
`python3 -m http.server 8000 --bind 127.0.0.1`
и открыть `http://127.0.0.1:8000/`.
Сервер запускать только на время проверки.

## Маршруты

- Открыть `#/`, `#/directions` и три `#/course/…`: oge, base, profile.
- Проверить `#/about`, `#/account`, `#/lesson/powers` и неизвестный маршрут.
- Проверить каждый раздел урока: meaning, zero, negative, properties, signs, example.
- Проверить прямую ссылку, перезагрузку, переход назад/вперёд,
  повторный переход по текущей ссылке, хлебные крошки и кнопку «Наверх».
- Убедиться, что виден нужный экран, меняется заголовок документа,
  фокус и прокрутка попадают в ожидаемое место.

## Демонстрационный вход

- Пустые поля не допускают к проверке; любой непустой текст допускает.
- Показ и скрытие пароля работают.
- Незавершённый ползунок возвращается в начало; завершённый открывает капчу.
- Проверить мышь, касание и клавиатуру, включая стрелки и End.
- Проверить неверный порядок чисел, правильный порядок, обновление чисел,
  закрытие кнопкой, Escape и кликом вне диалога.
- Проверить заглушку кабинета, выход, очистку полей при уходе и сброс входа
  после перезагрузки. Не использовать реальные пароли и данные учеников.

## Интерфейс

- Широкий и узкий экран: читаемость, отсутствие случайного горизонтального
  переполнения, формулы и дроби, карточки, форма, содержание урока.
- Навигация клавишей Tab, видимый фокус, ссылка перехода к содержимому,
  доступность кнопок и диалога.
- Режим уменьшения анимации и сообщение при отключённом JavaScript.
- Проверить консоль браузера и неуспешные запросы ресурсов.

## Порядок проверки изменений

Для новой функциональности выполнять применимые проверки; при появлении
инфраструктуры автоматизации в первую очередь покрыть маршруты и демовход.
Не добавлять фиктивные тесты ради отчёта.

Для изменений только документации достаточно проверить состав diff, ссылки,
согласованность описания с кодом и неизменность файлов сайта.
Браузерные проверки для такого изменения не выдавать за выполненные.

Записывать дату, проверенный коммит, браузер/устройство, сценарии, результат
и пропущенные проверки. Наличие этого списка не означает его прохождение.
